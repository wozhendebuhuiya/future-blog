# 前端转型 AI 全栈 - 学习路线追踪

## 背景

用户是 5 年前端开发经验，能够完成项目从 0 到 1，但理论基础薄弱。目标：转型为 AI 全栈工程师。

## 学习路线总览（6 个月）

```
阶段 1：计算机基础 + JS 深入（月份 1-2）
阶段 2：浏览器原理 + 框架原理（月份 3-4）
阶段 3：系统设计 + 设计模式（月份 5）
阶段 4：AI 应用开发（月份 6）
```

## 阶段 1：计算机基础 + JS 深入

### 数据结构（2-3 周）
- 栈、队列、链表、树（DOM 树 / AST）、哈希表、图
- 目标：知道每种结构的特性、适用场景

### 算法（2 周）
- 排序（快排）、搜索（二分）、递归、动态规划（入门）
- 目标：能分析常见前端操作的复杂度（如 diff 算法 O(n)）
- 练习：LeetCode 简单/中等各 30 道

### 网络协议（2 周）★ 重点
- HTTP/HTTPS 完整流程、TCP 三次握手/四次挥手
- 缓存策略（强缓存/协商缓存）、HTTP2/3
- 目标：前端面试和性能优化的基石

### 操作系统入门（1 周）
- 进程与线程、事件循环（宏任务/微任务）、内存管理
- 目标：理解 JS 单线程 + 事件循环

### JS 深入
- 原型链、闭包、作用域链、this 绑定规则
- Promise/A+ 规范、迭代器/生成器、Proxy/Reflect

### 推荐资料
- 书籍：《图解 HTTP》《网络是怎么连接的》
- 算法可视化：visualgo.net

## AI 使用规则

1. **每次用户提问时**，先判断当前问题涉及哪个学习阶段的技术，然后告诉用户"你当前问题的技术属于阶段 X——XXX"，并在最后简要说明当前整体进度。

2. **记录学习进度**：当用户在某个阶段完成具体学习任务时，在回答中标注进度。

3. **引导而非直接给代码**：作为老师角色，当用户的问题涉及当前学习阶段的技术时，先解释原理和 API，引导用户自己实现，而不是直接给出完整代码。

4. **阶段性总结**：当用户完成一个里程碑后，帮助总结该阶段的学习成果和注意事项。

5. **跨阶段提醒**：当用户的问题涉及还没学到的阶段内容时，先告知"这个技术属于阶段 X，建议先完成阶段 Y 的基础学习"，然后根据情况决定是否简单介绍。

6. **理论与实践结合**：每学完一个知识点，如果在用户的 `future` 项目中能找到对应的练手场景（例如学了缓存策略后优化 API 请求、学了设计模式后重构现有代码），必须主动引导用户在项目中进行实践。具体做法：
   - 在讲解完知识点后，扫描 `future` 项目的代码，找到可以应用该知识的地方
   - 给出实践建议："这个知识点可以在你项目的 XXX 文件中练习，你可以尝试 XXX"
   - 如果项目中没有现成的场景，建议一个小的练手模块（如在项目中新建一个 demo 页面或工具函数）

7. **实战对比**：在完成一个知识点的学习和实践后，主动告诉用户在真实项目中通常怎么处理：
   - 是用现成库/框架内置功能，还是手写
   - 用现成方案时配置一行 vs 手写的区别
   - 例如："ETag 你手写了一遍，但实际项目里 Express 一行 `app.set('etag', 'strong')` 就搞定了。手写是为了理解原理，不是以后每次都手写。"

8. **给出选项 + 建议**：当学习路程面临多个可选方向时，以表格列出选项的同时，必须给出推荐建议和理由。格式为"建议选 X，因为……"

# 设计模式练习区 (Design Patterns Practice)

欢迎来到设计模式练习区！在这个专区里，我们将通过实际的代码示例来学习和理解常见的设计模式。

## 为什么要学习设计模式？

对于一名前端/全栈开发者（特别是从 Vue 转向 React，并且关注架构设计和个人竞争力的你），学习设计模式有以下几个核心价值：

1. **提升架构思维 (System Design)**：面对复杂业务时，不再是“面条代码”，而是能设计出高内聚、低耦合的系统。
2. **解决问题的通用语言**：设计模式是前人总结的“最佳实践套路”，能帮助你和高级开发者同频对话。
3. **拥抱 AI 时代的核心竞争力**：AI 擅长写具体的函数，但人类开发者的核心价值在于“系统设计”和“业务建模”。掌握设计模式能让你站在更高的视角指挥 AI。

## 学习路线图 (Roadmap)

我们将结合 TypeScript 和 React/前端常见场景，逐步攻克以下核心模式：

### 1. 创建型模式 (Creational Patterns) - 关注如何创建对象
- [ ] 单例模式 (Singleton) - 全局唯一实例 (如：全局状态管理、配置中心)
- [ ] 工厂模式 (Factory) - 封装创建逻辑 (如：不同类型弹窗的统一创建)
- [ ] 建造者模式 (Builder) - 复杂对象的组装

### 2. 结构型模式 (Structural Patterns) - 关注类和对象的组合
- [ ] 代理模式 (Proxy) - 控制对象访问 (如：Vue3 的响应式原理、请求拦截器)
- [ ] 装饰器模式 (Decorator) - 动态添加功能 (如：React 高阶组件 HOC)
- [ ] 适配器模式 (Adapter) - 接口转换 (如：封装不同后端 API 返回的数据格式)

### 3. 行为型模式 (Behavioral Patterns) - 关注对象之间的通信
- [ ] 观察者/发布订阅模式 (Observer/Pub-Sub) - 状态变更通知 (如：Redux/Zustand 核心机制、Vue 的 EventBus)
- [ ] 策略模式 (Strategy) - 消除 if-else (如：不同会员等级的折扣计算)
- [ ] 状态模式 (State) - 状态机流转 (如：复杂表单/订单状态管理)

---
> “不要为了使用设计模式而使用设计模式，而是当代码出现坏味道、或者预见到未来的扩展需求时，自然而然地引入它们。”

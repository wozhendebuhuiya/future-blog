# 🚀 前端进阶全栈架构师：实战学习计划 (Roadmap)

你已经打通了前端(React)到后端(Node.js)的数据流向，这是从 0 到 1 的质变。
为了应对 AI 时代的职业挑战，接下来的核心策略是：**“以战养战”**。用全栈项目做战场，在其中融合高级架构思维和设计模式。

---

## 🟢 阶段一：夯实后端基础与前后端交互 (预计 1-2 周)
**目标**：不再只是获取写死的数据，而是让前端能向后端发送指令，后端能根据指令处理逻辑。

*   [ ] **1. POST 请求与参数解析**：
    *   前端：使用 `fetch` 发送带 Body 的 POST 请求（如登录表单）。
    *   后端：Express 接收并验证 `req.body` 参数。
*   [ ] **2. 后端路由架构拆分**：
    *   痛点：所有接口都写在 `server/index.ts` 里会爆炸。
    *   架构：引入 **MVC 模式 (Model-View-Controller)**，将路由(Routes)和业务逻辑(Controllers)分离。
*   [ ] **3. 中间件与【代理/装饰器模式】**：
    *   学习 Express 中间件的“洋葱模型”。
    *   实战：写一个“全局错误捕获”中间件和一个“打印请求日志”中间件。

## 🟡 阶段二：攻克数据堡垒 (数据库与持久化) (预计 2 周)
**目标**：让数据真正存下来，理解现代后端的 ORM 玩法。

*   [ ] **1. 数据库接入 (SQLite/PostgreSQL + Prisma)**：
    *   放弃裸写枯燥的 SQL，直接使用现代前端最爱的 **Prisma ORM**。
    *   实战：在项目中建两张表：`User` (用户) 和 `Post` (文章)。
*   [ ] **2. 数据库连接池与【单例模式】**：
    *   实战：在后端用单例模式封装 Prisma Client，防止每次请求都重新连接数据库导致内存泄漏。
*   [ ] **3. 真正的增删改查 (CRUD)**：
    *   前端写一个“发布文章”的表单，后端把数据存进数据库，前端再拉取最新的文章列表。

## 🟠 阶段三：全栈的核心痛点 (状态、鉴权与安全) (预计 2 周)
**目标**：掌握真实商业项目的登录系统和复杂状态管理。

*   [ ] **1. 认证鉴权 (JWT - JSON Web Token)**：
    *   全栈最难的一关：登录。
    *   实战：后端生成 JWT，前端保存 Token，后续请求自动带上 Token（结合 Axios/Fetch 二次封装 + **【代理模式】**）。
*   [ ] **2. 前端复杂状态管理 (Zustand)**：
    *   当组件越来越多，`useState` 不够用了。
    *   实战：学习轻量级状态库 Zustand（完美平替 Vue 的 Pinia），理解背后的**【观察者模式/发布订阅模式】**。
*   [ ] **3. 前端数据拉取优化 (React Query/SWR)**：
    *   放弃手动写 `useEffect` 发请求！使用现代的 SWR/React Query，自带缓存、重试、防抖。

## 🔴 阶段四：终极杀器 (Next.js 与部署) (预计 2 周)
**目标**：把之前学到的 Node.js 和 React 经验，无缝平移到现代全栈框架，并发布上线。

*   [ ] **1. 拥抱 Next.js**：
    *   理解为什么需要 SSR (服务端渲染) 和 SEO。
    *   理解 Next.js 的 Api Routes (其实就是我们刚学的 Express 的进化版)。
*   [ ] **2. 项目重构**：
    *   把我们这个用 Vite+Express 拼凑的项目，用 Next.js 重构为一体化工程。
*   [ ] **3. CI/CD 与自动化部署**：
    *   把项目部署到 Vercel (前端) + Render/Railway (数据库)。
    *   了解 Docker 基础。
